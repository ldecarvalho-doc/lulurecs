contributing to lulurecs ✦

← back to the site admin page repo ↗

⚠️ This is beta — expect it to change

Right now contributing means editing the site's data directly through a browser admin page, backed by GitHub. It works, but it's a homemade setup with rough edges: there's no login, no undo button, and no review step — whatever you save goes live within about a minute.

If more people start contributing, this will likely be replaced by something friendlier (proper accounts, or a suggest-and-approve flow where Lu reviews additions before they publish). So: don't get too attached to this workflow, and ask Lu before doing anything drastic.

What you'll be able to do

You canPlease don't
Add new recs, edit descriptions, fix links and typos, add tags, build and edit rec lists. Change or invent Lu's ratings (the stars are her opinion), rewrite her notes, delete entries you didn't add, or edit the site's code.

Getting set up (once, ~5 minutes)

1

Get invited

You need a GitHub account (free). Send Lu your username — she'll add you as a collaborator on the repo, and GitHub will email you an invite. Accept it before going further.

2

Create your access token

This is the password-like string that lets the admin page save on your behalf. On GitHub: Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic).

  • Note: something like lulurecs admin
  • Expiration: pick a date — 90 days is sensible
  • Scopes: tick repo

Copy the token when it appears — GitHub only shows it once. It must be the classic kind: GitHub's newer fine-grained tokens don't work on repos you don't own.

⚠️ That token can also reach your own repositories, so treat it like a password: never paste it in a chat, never commit it anywhere, and don't use it on a shared computer. If it ever leaks, delete it on GitHub and make a new one.

3

Connect

Open the admin page, paste your token, hit Connect. It's stored only in your own browser — there's a "Forget token" button when you're done, which is worth using on any computer that isn't yours.

Adding a rec

In the Recs tab, pick the category, hit + New rec, and fill in the form. What matters:

  • Title — the commonly used English title. The id fills itself in.
  • Type / country / year — country is a two-letter code (TH, KR, JP), which becomes the little flag.
  • Description — a neutral, spoiler-light synopsis in English. Two or three sentences. This is the "what is this" part, not the "is it good" part.
  • Notes — the personal take. Since this site is written in Lu's voice, sign yours, e.g. "(Jess) the pacing drags in the middle but the ending destroyed me".
  • Rating — leave this empty unless Lu gave you a number. The stars are hers.
  • Tags — comma separated, lowercase, hyphens instead of spaces (slow-burn, not Slow Burn). Reuse tags that already exist rather than inventing near-duplicates; check the sidebar on the main site for what's in use.
  • Links — one per line as Label | https://url. Official sources only (the studio's own YouTube channel, Netflix, Viki, iQIYI...), and please actually open the link to confirm it plays. Dead links are the main thing that rots on this site.
  • Poster — a TMDB image URL, or leave it blank for a colored placeholder.

Saving your work

Changes stack up locally until you press Commit to GitHub in the bar at the bottom — nothing is live before that. Write a short message describing what you did ("add 3 Taiwanese BLs"), commit, and the site updates in about a minute. A confirmation box gives you a link to check exactly what was saved.

A few habits that keep things tidy:

  • Commit in small batches rather than one giant edit session.
  • If you're adding lots of recs, use the checkboxes and bulk actions to tag them or add them to a list in one go.
  • Refresh the admin page before starting, so you're working from the latest version — several people editing at once can overwrite each other.

If something goes wrong

Don't panic, and don't try to fix it by deleting things. Every save is a git commit, so anything can be restored — tell Lu what happened and roughly when, and it's a one-command undo. Genuinely: breaking something recoverable is fine, quietly leaving it broken is worse.

Questions worth asking first

  • Adding a whole new category, or renaming tags across lots of entries.
  • Anything that touches entries you didn't write.
  • Whether a show belongs in one category or another — the lines here are deliberate (Korean BL lives with the other BLs, not with the K-dramas).

That's it. Thank you for helping — and please keep the notes fun. 💜
